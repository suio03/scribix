# OpusClip / Quso：同素材项目实操调研

调研日期：2026-09-16。用户授权进入已生成完成的两个项目进行交互调研。素材均为 `The Good Woman Trap.mp4`；Quso 自定义时间范围显示原视频长 59:21.058。

## 结论

值得学习的是「批量候选 → 排序筛选 → 带成片效果预览 → 修正 → 导出」的工作流。不能仅把 Scribix 的 5 条改成 39 条。

本素材中，Opus 生成 39 条、Quso 生成 23 条短片，但两者片段时长简单相加分别为 19:35 和 18:25，接近。主要差异之一是截取粒度：Opus 中位数 23 秒，Quso 中位数 51 秒。同一观点会被 Opus 截成金句、被 Quso 保留成较长论述。这是本次样本观察，不代表两家所有素材的默认策略。后续用户提供生成前录屏，补充确认 Opus 提交前可见长度为 Auto (0m–3m)，不是被用户限定为 30 秒以内；详见文末补充。

## 结果页与筛选流程

### Opus

- 网格一次呈现多个竖屏成片预览，带标题、时长、编辑/下载/发布入口。点击标题可打开详情弹层，不必进入编辑器。
- 列表视图把预览、文字稿/Scene analysis、操作并排放置。优点是可直接阅读内容判断完整性；代价是每条占据较多页面空间。
- 默认排序菜单选中 Virality score，另有 Chronological。本账号检查到的卡片没有显示数值分数；不能据此声称没有评分系统。
- Filter 包含 Favorited、Disliked、Edited、Dubbed、Not dubbed 和 `<180s`。当前若干状态选项为 disabled；不推断是付费还是没有匹配内容所致。
- Select 模式提供 Select all、Bulk schedule、Bulk download、Bulk dub。未选择时批量操作 disabled；未实际执行批量任务。
- 列表/详情提供 Favorite、Dislike、Duplicate、AI tools、画幅、XML 导出、HD 下载、付费 upscale 等入口。看见入口不等于全部完成验证。
- 部分尚未就绪的预览最初显示 Unable to play media，后续滚动加载后出现时长/预览；不将瞬时状态统计为永久失败率。

### Quso

- 左侧紧凑列表、右侧一个大预览。浏览多条时可留在同一屏幕，适合逐条筛选。
- 列表同时给排名、标题、时长、原片起止和 Score。23 条分数从 99 到 75，近似逐级递减；点击 99 未得到可见评分解释，不能把这些数值当成校准过的传播概率。
- Filter 包含 All clips、Liked clips、Intelliclips；Sort 包含分数升降、时长升降、原时间先后。未验证 Intelliclips 的生成机制。
- 片段标题可在结果页编辑；有收藏、反馈、Edit、下载、Share to social。
- AI Tools 实际展开为 CutMagic 自动场景检测，以及 Remove Silences & filler words 开关。没有因名称推断它支持重新按主题选片。

其他发现：

1. **广告被当作高位候选。** Opus 第 4 条 The Invisible Load，约 12:59–13:53，文字稿包含保险服务宣传和询价引导，末尾又带到下一段话题。标题听起来像观点内容，实际主要是赞助口播。需要广告识别及话题边界复审。
2. **高位候选仍依赖上下文。** Opus 第 2 条开头指代不明，后面才提及人物；第 3 条也从对前文的回应开始。不是所有候选都有独立、明确的开场。
3. **自动包装可能改变主题。** Opus 最后一条标题 Team Motivation，实际原文上下文是母亲如何奖励孩子完成家庭责任。Quso 完整原文面板可交叉核对，提到了孩子、玩具和建立图书收藏。标题把家庭协作泛化成团队管理，有误导风险。
4. **非连续剪辑已实际存在。** Opus 最后一条显示 15:57–16:12 和 16:28–16:35 两个区间；第 5 条也如此。不能把它的所有输出理解为一组单一起止点。
5. **长片段也未必有强开头。** Quso 第一条仍以回应前文的语气开始，第二条保留了枚举中的第一点开场。多保留上下文有价值，但不能免除开头审查。

这些是人工文本与界面检查结果，不是平台传播效果实验，也不能据此给两家整体选片能力排名。

## 编辑：Quso 可实操部分

- 进入编辑器后有 Templates、CutMagic、Transcript、Subtitles、Elements、Media、Text、Background、Description。
- Transcript 中，片段前后未采用原文以灰色删除线保留；采用部分为正常正文。这让用户理解截取范围，不必离开编辑器返回整段原视频找上下文。
- 实际拖选采用部分文字后出现 Remove 和 Keep only this。没有执行删除，因此只确认交互入口，不声称完成了文字剪辑保存与导出验证。
- 时间轴默认可折叠，展开后有波形、选段、缩放、Fit、分割、逐帧与前后跳转。用户不必先面对完整时间轴。
- CutMagic 以 Scene 为单位设置起点和布局；可在当前播放位置添加场景。菜单包括 1–4 人、屏幕+单人/双人/气泡、Screen Only、Full Frame。界面提示仅支持 Portrait 9:16；未逐项应用和验收。
- 字幕提供逐词颜色、单词/双词、文字出现、背景变化等样式，字体/大小/对齐、Auto Position；预览播放可看到字幕及原文逐词高亮。
- 顶部把 Save Template、Save Draft 和 Download 分开。下载再提供 Download / Publish & Schedule；当前 Download 随后被升级弹层拦住。
- Custom clip 有从时间范围与从文字稿创建两条路线。前者包含标题、起止输入、范围滑块；后者包含完整原文和 Preview and create。未提交创建。

## 对照 Scribix 当前本地实现

只读取代码，未修改功能，也未把本地实现当作生产部署证明。

- `lib/video-workspace/contracts.ts`：`maxCandidates: 5`、`maxAiCandidateDurationMs: 45_000`；`PREVIEW_PROXY_AUTO_CANDIDATES` 直接引用 maxCandidates。
- `lib/video-workspace/candidate-generation.ts`：AI 最短 15 秒，`AI_CLIP_MAX_SEGMENTS = 1`；短素材数量规则为 1 / 3 / 最多 5，长素材分批分析；已有生成后完整性复审结构及 45 秒前后文窗口。
- `docs/roadmap/video-product-plan.md` 已记录推荐理由、完整性复审、手动原视频选片、标题封面与发布材料等现有能力。不能把竞品里看到的所有入口都列成我们缺失的功能。

本次最需要重新评估的是三个约束：

1. **候选数量与素材长度。** 约一小时访谈仍最多 5 条，限制了可供用户挑选的主题范围。应按有效内容和主题覆盖产生一批候选，再优先呈现最佳子集；不要定额凑满，也不要因当前界面只能容纳几条就限制发现阶段。
2. **45 秒上限。** Quso 本次有 15/23 条超过 45 秒，Opus 也有 8/39 条。建议评估可选长度范围和约 60–90 秒的完整论述，先确认编辑、预览、成片、计费和资源限制，再定新的上限。竞品不是所有场景必须更长的证明。
3. **发现数量与预览成本的耦合。** 本地自动预览数量引用候选上限。不能只把 5 改成 30；需分别定义发现数量、优先显示数量、预览并发/预热数量、最终导出数量。两家低清预览给了产品层面的参照，但其私有调度架构未知。

## 建议的产品顺序（待决策，不是已批准开发项）

先做候选覆盖、完整性与筛选体验，再扩展复杂编辑：

1. 一次分析产生覆盖不同主题的候选集，按质量排序；前几条重点推荐，剩余可展开。数量随素材变化，允许不足。
2. 结果页同时提供标题、时长、原片范围、可核对推荐理由、文字内容和成片效果预览；提供待选/已选及批量导出入口。
3. 优先修正边界：保留可恢复的前后文，方便补上提问、答案或结尾。沿用已有完整性复审，并加入广告、断题、指代、标题忠实度、重复主题检查。
4. 分离候选发现、预览和高清导出，避免候选扩容直接放大首次等待与渲染成本。
5. 后续再评估非连续文字剪辑、多人物布局与节目模板。非连续剪辑需额外审查语义是否被重组改变，不宜仅因 Opus 已有就立刻复制。

验收重点：同一素材的主题覆盖、愿意保留/发布的条数、找出前三条所需时间、每条修正耗时、重复和广告占比、首个可播放预览的等待、每条可用输出成本。不要用候选总数和未校准的 virality 分数替代这些指标。

- 本条录制路径未出现片段数量、长度、主题提示、字幕模板或画幅选择。结论限于这条上传路径，不能推广为整个产品没有这些能力。

### 对前述建议的修正

1. **生成前要有“可直接开始、也可表达偏好”的入口。** Opus 的选项虽然多，但 Auto 和已有样式让用户可以不逐项配置。Quso 只强制选择语言。Scribix 可以提供默认方案，同时允许用户修改目标长度、关注主题、分析区间与统一样式，不应设计为先完成一份长表单。
2. **数量由系统发现，目标由用户表达。** 两条录制路径都没有要求用户输入生成条数；一个项目生成 39 或 23 条，是后续结果。我们的内部数量预算应与输入内容、质量与成本有关，不能将固定条数变成用户必须理解的生成参数。
3. **区分三个不同维度。** 分析原视频的哪个范围、每条结果希望多长、希望结果讲什么，需要分别表达，不能混成一个“选择片段”步骤。
4. **整批外观可提前设定。** Opus 提交前已选字幕与 9:16，解释了为什么结果一出现就像成片；生成后仍可单条修改。建议在 Scribix 复用已有字幕/标题能力提供批次默认，不重复开发编辑器。
5. **费用与等待属于核心流程。** 提交前展示预计成本；提交后明确上传与处理的区别、何时可以离开、在哪里回来找任务。ETA 应有估计依据；不能照搬 Quso 长时间停在低百分比的反馈，也不应承诺不可靠的精确完成时间。

据此建议的完整用户流程为：上传/导入 → 确认默认生成方案与预计成本（可展开长度、主题、范围、样式）→ 提交并在项目列表追踪 → 批量候选筛选 → 修正少数片段 → 导出/发布。此处仍是产品建议，不代表用户已批准实施这些变化。
