# Long video to clips：竞品功能与 Scribix 产品方向

调研日期：2026-09-08。范围：OpusClip、Vizard、Repurpose.io、Klap、quso.ai，并参考 Riverside、Descript。

依据为官方产品页、帮助中心、API 文档，以及 Scribix 当前本地代码。没有使用同一素材在各付费产品中跑成片，因此本文能确认公开功能和交互设计，不能确认实际选片质量、速度、效果排名或功能带来的收入提升。厂商的 viral、增长倍数和准确率宣称不作为效果证据；部分功能有套餐、平台或 Beta 限制。

> 本文保留 2026-09-08 调研与实施前代码快照，不继续更新功能差距和执行优先级。标题、发布文案、意图选片及社交发布已有后续实现；当前状态与顺序见[产品 plan](../roadmap/video-product-plan.md)。

## 1. 结论

Scribix 值得围绕长视频剪辑增加功能，但选择标准应是：它是否明显减少用户从原视频到愿意发布之间的工作。

建议聚焦有稳定长内容来源的播客、访谈和知识创作者。近期产品方向是：**从一段长谈话中，选出独立可理解的内容，配好字幕、画面、开头标题和发布文案，形成风格一致的一组短视频。**

推荐顺序：

1. 验证现有选片完整性、裁切稳定性和修改耗时，尤其检查 45 秒候选上限是否过窄。
2. 补齐发布成品包：开头标题、可用封面、按平台组织的发布文案。
3. 支持按主题或用途找片，减少用户反复碰运气。
4. 保存品牌样式并批量应用，减少重复劳动。
5. 根据真实修片障碍，再选择节奏清理、双人/屏幕布局、B-roll 或分发集成。

这是一组待用户样本验证的产品判断，不是已验证的市场需求排名。功能多不必然更吸引人；如果候选本身不完整，额外装饰也无法让用户愿意发布。

| 产品 | 公开工作流与附加能力 | 对 Scribix 的启发 |

| Vizard | 自动剪辑、字幕与表情、B-roll、文字剪辑、品牌模板、翻译、发布文案、社交发布、团队预览；Spark 增加多模态和提示词找片 | 同一原视频能服务不同主题和不同团队用途 |
| Repurpose.io | 连接来源和目的平台，自动转换、分发、排期与备份；可按描述里的时间戳生成 snippets | 持续省掉重复分发工作，也能成为主要购买理由 |
| Klap | 语音内容选片、字幕、品牌自定义、直接发布；AI Reframe 2 展示双人分屏、屏幕录制和游戏布局 | 画面布局要保留内容信息，不能只追踪一张脸 |

| Riverside | 录制与编辑链路中的 Magic Clips，主题/说话人选择、布局、声音处理和宣传素材 | 已掌握录制入口，剪辑是完整工作流的一环 |
| Descript | 文本式媒体编辑，辅以 Create Clips、声音修复、口头禅清理和眼神调整 | 用户可方便地修正 AI 输出，是购买价值的一部分 |

## 3. 他们是如何做到长转短的

从公开资料可归纳出六个环节，具体内部模型、训练数据和排序权重未公开，下面不是对厂商私有架构的还原。

1. **理解内容。** 将语音转为带时间信息的文字，结合说话人、画面与声音线索。OpusClip ClipAnything 和 Vizard Spark 宣称能处理少对白内容；Klap 明确说更擅长有讲话的视频。
2. **找到适合的片段。** 按内容价值、开头、完整性或用户提示词选择候选。Opus 的评分说明包含 Hook、Flow、Value、Trend；这是厂商排序工具，不是经过本次验证的爆款概率。
3. **整理叙事与节奏。** 调整开始和结束，部分功能可删除停顿、重复表达，或组合不同位置的内容。
4. **转换画面。** 跟随主体或说话人，并在多人、屏幕分享等场景切换布局。
5. **包装成片。** 字幕、开头标题、品牌、封面、B-roll、音乐等。
6. **进入发布流程。** 生成平台文案、导出、排期，或交给团队继续编辑。

证据：[ClipAnything 对 Basic 与多模态能力的区分](https://www.opus.pro/clipanything)、[Spark 工作方式及访问限制](https://help.vizard.ai/en/articles/9905409-what-is-spark-1-0)、[Klap 支持类型](https://klap.app/)、[Opus 评分维度](https://help.opus.pro/docs/article/virality-score)、[Vizard 社交发布 API](https://docs.vizard.ai/docs/publish-clips-to-social-media)。

对我们而言，语言内容可以先靠可靠的文字理解、精确的时间边界和稳定的人物布局做好。体育、游戏、旅行等视觉主导内容需要额外的视觉理解，不应将“已有说话人检测”宣传为“能理解任何视频”。

## 4. Scribix 已经具备什么，还有哪些差距

以下是本地实现核查，不等于本次已验证生产部署或真实输出质量。

| 能力 | 当前实现证据 | 产品差距或边界 |
| --- | --- | --- |
| 自动候选与完整性复审 | 候选生成后再独立检查上下文，允许零候选；按真实句子与 word 边界定位 | 需要实际素材验证“用户愿意发”的比例 |
| theme / hook / reason / score | 候选结构已有这些字段 | 当前候选卡主要展示主题与时长；检查的 UI 未见 hook/reason 的直接使用；不能等同于已有成片开头标题 |
| 自动说话人跟随 | 视频容器已有 MediaPipe + TalkNet，低置信度回退完整画面 | 不是双人同时分屏，也不是完整的屏幕内容理解；准确性仍需样本验证 |
| 字幕、样式、品牌素材、封面 | 编辑器与 RenderSpec 已有实现 | 单条可编辑不等同于跨项目保存节目预设、批量应用 |
| 修改片段边界 | 付费编辑可调整原视频起止；手动候选入口已存在 | 当前 UI 不提供任意内部切段、删段和重排；不能把改字幕说成删文字即可剪视频 |
| 长度与候选数量 | AI 候选 15–45 秒，手动编辑总长最多 60 秒；长于 3 分钟的原视频最多 5 个 AI 候选 | 对需要上下文的谈话可能过窄；属于待验证假设 |
| 重选片段 | 已生成 AI 候选后禁止任意重新生成 | 尚无按新主题重新找片的用户流程 |

## 5. 最值得做的附加功能

### A. 发布成品包：近期优先

每个用户选中的片段配套：可编辑的开头标题、封面文字、发布标题和简介，以及少量相关标签。文案根据最终剪辑内容生成，边界改变后提示更新，避免文案仍描述被剪掉的部分。

Opus 的 Auto headline 是出现在片头的一行文字，可以保存到品牌模板；Vizard 的发布 API 会生成帖子文案和标签。这说明“剪片后的最后几步”已是明确的竞争环节。[Opus Auto headline](https://help.opus.pro/docs/article/auto-headline)、[Vizard 发布说明](https://docs.vizard.ai/docs/publish-clips-to-social-media)。

最小版本建议：每条提供 2–3 个标题备选、一份平台文案、已有视频帧上的简洁封面排版。用原片支撑标题，不补造说话人的观点。Hook 元数据应作为草稿重新核对，不能原样当作已验证的宣传文案。

相对投入中等：文本生成便宜并不意味着整个功能只有一次模型调用；片头文字需要预览与最终渲染一致、字幕避让、可编辑与关闭。封面上传支持因平台而异，不能承诺所有平台都能直接使用外部封面。

### B. 按主题或用途选片：近期优先

让用户指定“找关于创业定价的建议”“只保留嘉宾讲失败经历的内容”“找可以独立回答问题的片段”。首次先提供几个清晰用途和一个可选主题输入，不要求用户会写复杂提示词。

竞品依据是 Opus 的提示词剪辑，以及 Vizard Spark 的按提示词提取、重新提示流程；Spark 文档仍写有 Beta 和访问限制，不能假定所有账号都有。[ClipAnything](https://www.opus.pro/clipanything)、[Spark](https://help.vizard.ai/en/articles/9905409-what-is-spark-1-0)。

Scribix 的第一版只检索与选取原文已有的内容，继续遵守完整性检查。对同一素材换主题，应明示处理额度、保留原有草稿，避免无限重试成本。这比一开始实现“找篮球进球”等视觉事件容易控制范围。

可见价值：AI 找到的内容更接近用户本来想表达的东西，而不只是系统认为分数最高的片段。

### C. 品牌记忆与批量应用：近期优先

将字幕样式、颜色、Logo、开头标题样式和封面样式保存为节目预设。下一次上传自动套用，并允许把样式应用到选中的多条候选，保留各条内容和剪辑边界。

Vizard 的品牌模板、Riverside 的比例/布局/品牌/长度预设都在解决反复设置问题。[Vizard 品牌模板说明](https://vizard.ai/)、[Riverside 预设](https://riverside.com/magic-clips)。

一个容易忽略的扩展是专有名词记忆，例如嘉宾姓名和品牌拼写。Opus 已有单片全文纠正和品牌词库。[Opus Brand Vocabulary](https://help.opus.pro/docs/article/brand-vocabulary)。建议先做项目内“同词一起修正”，再评估跨项目词库，避免错误替换被永久复制。

相对投入中等，复用现有样式基础；需要清晰区分“保存样式”“覆盖哪些片段”“保留单片调整”。这是持续更新节目的回访理由，实际留存提升仍需验证。

### D. 节奏与声音清理：根据修片记录提前或随后做

提供温和的长停顿缩短、重复表达标记、音量平衡，用户可预听和撤销。Opus 的 Speech Cleanup 支持按类型检查口头禅、调整停顿阈值、标记重录；Riverside 也提供停顿、音频和冗余片段处理。[Opus Speech Cleanup](https://help.opus.pro/docs/article/speech-cleanup)、[Riverside 编辑器工具](https://support.riverside.com/hc/en-us/articles/16673658517277-Riverside-editor-Overview)。

我们不能直接把这当成很小的功能：删内部停顿会产生多个剪辑段，当前 UI 和 segment 数量限制需要一起调整，还涉及字音边界、字幕时间与预览同步。先清理明确的长静音比自动重写、拼接整段谈话更稳妥。

### E. 双人分屏与屏幕内容布局：按目标素材决定

访谈可能需要同时保留两个人；教程更需要看清屏幕内容。Klap 的 Reframe 2 明确展示分屏与屏幕录制布局，Riverside 也有智能布局。[Klap](https://klap.app/)、[Riverside 工具概览](https://support.riverside.com/hc/en-us/articles/13315511579037-AI-Tools-Overview)。

如果首批用户主要是双人同框访谈，这项可进入第一批；如果主要是单人口播，先验证现有自动跟随即可。已有 face tracking 可复用，但布局识别与多区域渲染是额外工作。

### F. B-roll：有吸引力，但建议先做用户素材覆盖

B-roll 是说话时插入的辅助画面，如谈产品时展示产品录屏。Opus 支持按上下文加入 AI 图片或素材库视频，并允许调整位置、长度或重新生成。[Opus B-roll](https://help.opus.pro/docs/article/ai-broll)。

对 Scribix，优先考虑用户上传产品截图、录屏或已有图片，选一句话放上去，保留原音频。它更适合产品讲解，也更容易保证内容相关。再评估素材库检索和生成式视频。

完整自动 B-roll 的相对投入高：要解决匹配相关性、素材使用条件、缓存与合成、额外成本和用户修正。外观更丰富不等于内容更有效；本次没有证据证明加入 B-roll 必然提高我们的转化或观看量。

## 6. 有价值，但暂时不宜成为第一批范围

| 功能 | 什么时候值得做 | 当前判断 |
| --- | --- | --- |
| 多平台排期/自动发布 | 用户已经稳定产出且经常抱怨上传重复 | 先提供下载和文案，再接一个最常用平台；连接维护、失败重试和权限有持续成本 |
| 新视频自动导入 | 同一频道每周持续更新 | 是留存候选；先完成普通导入，不能把现有 YouTube 字幕导入当作视频素材导入 |
| 视频转 LinkedIn 帖子/Newsletter/文章 | 用户确实同时运营文字渠道 | 从同一片段配套短帖开始；整集生成大量文章可能分散主流程 |
| 双语字幕与翻译 | 有跨语言受众和明确需求 | 先验证一组语言，字幕翻译与配音、口型同步分别评估 |
| 客户预览、批注、团队审批 | 出现代运营/代理团队客户 | 有机会提升团队价值，个人创作者阶段先不重做协作平台 |
| Premiere / DaVinci 导出 | 用户愿意在专业编辑器接着修 | 高阶出口；Opus XML 有字幕表现、逐条导出等边界，不能当无损通用工程格式 |
| 表现分析与下一次选片建议 | 有持续发布数据及足够账号样本 | 不能凭模型评分假装已经知道真实传播效果 |
| AI 眼神、分身、配音、泛视频 Agent | 特定用户愿意为此付费 | 与现有长谈话剪辑主线距离较远，暂缓 |

来源：[Opus 自动导入与额度](https://help.opus.pro/docs/article/auto-import)、[Vizard 发布](https://docs.vizard.ai/docs/publish-clips-to-social-media)、[quso 文字内容与分析](https://helpdesk.quso.ai/help/welcome-to-qusoai)、[Vizard 团队与翻译](https://vizard.ai/)、[Opus XML 限制](https://help.opus.pro/docs/article/import-to-adobe-premiere)、[Riverside AI 工具](https://support.riverside.com/hc/en-us/articles/13315511579037-AI-Tools-Overview)。

## 7. 比附加功能更需要先确认的产品限制

**45 秒是否让选片过度保守？** 我们要求独立完整，同时固定 AI 候选最多 45 秒，可能排除不错的故事或回答。先用同一批素材比较当前范围与较宽候选范围，例如实验中的 30–90 秒；保留完整性门槛，衡量多出来的内容是否真的有人选。这个实验建议没有修改现有长度合同。

**最多五条是否够用？** 五条有价值的内容可能优于几十条重复内容。应看用户最终采用数量、主题覆盖和是否还需要继续找，不能仅按竞品首页的数量宣传扩容。

**免费用户能否感受到完成后的价值？** 当前免费用户能导出 AI 原始剪辑，但不能进入付费编辑。若默认输出必须经过大量修正才可用，用户可能在付费前流失。先观察实际输出及试用行为，再决定是否让用户体验一条完整包装效果；本文不建议直接改套餐或开放无限编辑。

**已有能力是否可见？** 内部 hook/reason 字段可以为用户提供选片解释或标题草稿，但要展示简短、具体、可核对的理由。没有必要为了显得 AI 强大，给未经校准的分数加上“爆款概率”。

## 8. 建议的下一轮验证

这部分是后续实验设计，本次未执行成片盲测或联系用户。

1. 准备约 10 段有使用权限的素材，覆盖单人口播、双人访谈、远程对谈、屏幕演示和上下文较长的问答。
2. 用相同素材与相近设置比较 Scribix、OpusClip、Vizard；分别记录默认结果和调整后的结果，记录套餐与功能是否可用，不凭首页视频排名。
3. 找 5–8 位目标创作者评审，尽量隐藏工具名称。问“你愿意发哪条”“还要改什么”，并观察实际修改过程。小样本只用于发现问题，不推算整个市场比例。
4. 记录：独立可理解的候选比例、愿意发布的比例、完成一条的人工操作时间、等待时间、裁切/字幕问题、每条可用成片成本。
5. 用同一片段比较原始剪辑与增加标题/品牌/文案后的版本，判断附加功能是否减少剩余工作；关注下一次真实上传，而不只问用户喜欢什么功能。

优先级随证据调整：没有可用候选就先改选片；内容好但画面不能用就先改布局；大量时间花在包装就推进成品包和预设；已能持续成片但发布麻烦再推进分发。

产品事件沿用 [现有视频跟踪约定](../video-workspace/tracking.md)，不新增跟踪数据库或回放基础设施。现有下载事件只表示发起下载，不能用它直接证明用户实际发布。首轮可以用人工记录和自愿提供的发布反馈补充。

## 9. 建议对外表达的方向

“Long video to clips” 继续承担用户识别与 SEO 入口。价值说明可围绕：

> 把播客和访谈中值得分享的内容，做成带字幕、统一品牌和发布文案的短视频。

这是目标定位草案，其中尚未实现的配套能力必须完成验证后才能对外承诺。演示应使用同一份真实原片，展示选中内容、自动画面处理、少量修改和最终成片，遵守 [首页素材与演示边界](../homepage-media.md)。

第一阶段最值得争取的体验是：用户选到合适内容，确认标题和样式后就能拿去发布。产品承诺应以实际可用输出和节省的步骤为证据。
