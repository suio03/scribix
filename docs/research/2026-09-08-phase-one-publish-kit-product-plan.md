# Scribix 首期产品方案：按用户意图选片，完成可发布作品

日期：2026-09-08。状态：首期代码已在本地实现；登录后的完整流程与无指导用户任务仍待验收，尚未部署。套餐、额度和保留期限不变。实现、迁移顺序与验证边界见[发布准备技术约定](../video-workspace/publish-preparation.md)。

本版取代首期仅覆盖发布包装的范围：首次生成时按需求选片提前进入首期；已有候选后换方向继续找片仍后置。文件路径保留，避免已有链接失效。

依据：[竞品调研](./2026-09-08-clipping-competitor-product-research.md)、[完整产品路线图](./2026-09-08-clipping-product-roadmap.md)，以及本次本地代码复核。竞品依据沿用当日调研，未新增竞品成片测试；本地实现不等于生产效果验证。

## 1. 产品方向与首期目标

长期方向：帮助持续更新长内容的创作者，把一期内容做成一组可发布、风格一致的社交短视频。

首期覆盖从意图到作品的闭环：用户选择自动推荐，或说明本次想分享的主题与内容类型；AI 从原片中找出符合要求且独立完整的候选；用户选择其中一条，在 Scribix 内完成片头标题、字幕与画面确认、封面和发布文案。

用户任务：

> 我有一期播客、访谈或知识讲解，想分享其中某个主题的观点或经验。我希望能告诉工具这次想找什么，再把合适的片段准备成可发布作品，不用自己翻找整段视频，也不用到多个工具补齐包装。

首期价值是让候选更接近用户本次的表达目的，并减少成片和发布准备工作。用户决定想找什么；AI 必须验证原片是否支持、片段能否独立理解。新增粉丝、播放增长与获客是后续目的，首期不承诺这些结果。

首批适用对象是自己制作与发布内容的个人创作者和小团队。素材以有清晰讲话内容的视频为主；该选择来自现有语音选片与人物构图基础，不来自某个 SEO 关键词的搜索量。

## 2. 为什么先做这一步

竞品调研显示三类连续工作：按意图找内容、包装成片、持续制作和分发。OpusClip、Vizard 提供提示词找片，并覆盖标题、品牌与发布文案；Repurpose 更侧重自动分发。首期补齐前两类工作的最小闭环：如果候选偏离用户本次想表达的内容，包装无法弥补这个问题。

实施前本地已有候选、独立片段草稿、字幕与品牌控制、封面选帧和最终导出。当时缺少首次选片意图入口与匹配校验、片头标题合成、独立封面文字排版、根据最终片段组织的发布文案，以及这些材料的一致性管理。

因此首期完成“首次按意图找片 → 单条作品发布准备”，下一阶段再接已有结果后的继续找片、节目预设和批量制作。核心选片或构图若有阻断问题，同批修复；不把整个 P0 清单重新开发一遍作为无限期前置条件。

## 3. 范围决策

| 项目 | 首期决策 |
| --- | --- |
| 选片入口 | 默认自动推荐；可选“按我的需求找片段”，指定一种内容类型及可选主题 |
| 选片边界 | 仅基于原片讲话内容；匹配、完整性和现有时长合同同时满足；允许零结果 |
| 生成次数 | 首次生成使用一组条件；成功产生候选后不开放换方向重选；零匹配提供一次受控调整机会，详见 5.1 |
| 工作单位 | 当前选中的一条片段；AI 候选与已有手动片段都适用 |
| 视频 | 沿用现有竖屏 MP4 输出、字幕、构图和品牌控制 |
| 片头标题 | 生成 3 个候选，选择、编辑、关闭；显示在视频开头 |
| 封面 | 从最终片段选帧，加可编辑标题，导出独立图片 |
| 发布文案 | 提供一份简洁的跨平台基础文案：标题、正文、最多 5 个相关标签；分别或整体复制 |
| 语言 | 默认跟随片段主要语言，用户可手动编辑；首期不提供翻译或跨语言改写入口 |
| 交付 | 集中下载当前片段的视频、封面和 UTF-8 文案文件；提供 ZIP，也保留单独下载和复制 |
| 免费与付费 | 首次按需求选片向免费及付费用户开放，沿用候选额度；新增编辑与发布材料能力沿用付费编辑权限 |
| 多平台差异 | 首期不做三套平台生成器，不承诺平台规格自动适配或一键发布 |

“一份基础文案”是刻意控制的首期范围：标题可用于视频标题，正文可用于帖子描述，用户按目的平台取用。后续有真实改写需求再增加平台版本。

## 4. 用户流程与界面组织

1. **上传并选择找片方式。** 在首次候选生成之前展示自动推荐／按需求找片。上传或转写可以先进行，候选分析必须等待用户确认条件；不可先自动生成，再展示一个无效的意图入口。
2. **查看候选。** 分析中和结果页保留本次条件摘要，每条显示简短推荐／匹配理由。零匹配走明确的调整流程，不悄悄切换自动推荐。
3. **确认内容。** 选择一条，进入已有编辑器调整起止、字幕和构图；免费用户沿用原始候选预览与导出，编辑入口遵循付费边界。
4. **准备发布材料。** 编辑器内增加“发布准备”入口，用户主动生成。读取当前已保存的片段，返回标题备选与文案，同时为封面填入标题草稿。
5. **确认包装。** 用户选一个片头标题，在实际视频上预览；可编辑或关闭。封面可换帧、改标题、改有限样式。文案直接编辑和复制。
6. **导出与回来继续。** 同一入口展示视频、封面和文案状态，下载当前版本发布包或单项材料。再次打开恢复保存的内容，不自动重新生成候选或文案。

已有候选的项目直接进入原有结果与编辑流程，不能借新增入口绕过重选限制。走现有短源视频直接编辑路径的项目无需填写找片条件，直接进入单片编辑和发布准备。

界面整合：片头标题、封面与文案属于同一发布准备流程；扩展或迁移现有封面控件，不再保留两个互相独立的封面编辑入口。播放预览保持可见，避免为了改一句标题来回跳页。

不要求先填社交账号、品牌资料或内容策略问卷。内部项目标题继续用于识别片段，与片头标题、封面标题、发布标题分开保存；修改其中一个不会暗中改写其他字段。

## 5. 功能细则

### 5.1 首次按需求选片

**输入方式**

- 自动推荐为默认，不强制填写需求。按需求模式提供单选类型：不限、实用建议、观点与讨论、故事与经历、问题解答；可补充最多 300 个 Unicode 字符的主题描述，前后端使用一致计数。
- 类型非“不限”时主题可空；类型“不限”且主题为空时按自动推荐处理，界面明确展示。只输入“找精彩片段”等泛化要求，可归为自动推荐并显示实际使用模式，不推测不存在的具体主题。
- 示例：“嘉宾谈第一次创业失败，以及学到的教训。”说明：“只从这段视频已有的讲话内容中选择，不生成新内容或查找外部素材。”
- 首期不提供独立说话人筛选器。主题描述可提及嘉宾，但仅在转写上下文能确认身份时使用该条件；身份不明则提示改为主题条件，不能猜测声纹或人物身份。
- 一次只支持一个主要主题和一种类型；矛盾或过于复杂的要求提示简化。视觉事件、背景音乐、外部检索、成片时长修改等不支持的要求，生成前说明边界，不执行、不静默删除条件。

**匹配与真实性**

- 先解释需求是否在支持范围，再按结构化条件寻找候选，最后同时检查匹配、原文依据、独立完整性和现有时间边界。需求和转写均作为数据处理，不得覆盖系统选片规则。
- 用户指定主题／类型是候选筛选条件，不只是提高排名的偏好。找不到足量匹配项可以少返回，不能拿通用片段补满数量。
- 延续现有 AI 候选 15–45 秒及候选数量规则，不因指令要求绕过。相关内容若无法在现有长度内独立成片，说明“未找到符合条件且能在当前长度内独立成片的片段”，不能断言原视频完全没有该主题。
- 要求“嘉宾承认产品无效”时，仅接受原文明确支持的候选；不靠去掉否定、拼接或补写制造结论。选片意图不能直接成为后续标题／文案的事实来源。
- 每条结果展示一句可核对的匹配理由，例如“这一段讲述定价失败，并给出调整方法”；不显示未经校准的匹配百分比或爆款概率。

**零结果与重试**

- 区分不支持的需求、正常零匹配与技术失败。不支持的需求在候选生成前返回；技术失败保留原条件重试，并沿用服务端幂等、限流与任务重试约束。
- 正常零匹配后，允许一次额外的用户主动生成：修改条件，或显式切换自动推荐。两者共用一次机会；不能自动放宽、自动生成或重复转写扣分钟。
- 首次开始前说明“未找到时可调整一次”；零结果页显示剩余机会。第二次仍为空则停止 AI 查找，提供已存在的手动剪辑入口并说明套餐权限，不要求用户重新上传绕过限制。
- 任一次成功产生候选后，本项目首期找片结束，即使结果数量少也不再换方向。已产出候选后的重选、保留多批结果及跨批去重属于后续范围。
- 次数与任务状态由服务端记录；双击、刷新、并发、多标签页不能多消耗机会或绕过上限。零匹配的调整不是技术失败重试，不能混用计数。
- 保存实际执行的规范化条件与生成结果关联，结果页可回看。用户重新打开页面不会执行新请求；需求全文不进入分析事件。

### 5.2 片头标题

- 基于当前最终片段提供 3 个可选择的标题草稿，突出明确观点或问题，不虚构数字、结论、引语或承诺。信息不足时允许用户手写，不凑造候选。
- 原有候选 `hook` 仅作参考，不能不核对就直接烧录到视频。
- 用户可以编辑文字、关闭标题，并在片头显示 2–5 秒，默认 3 秒；短于所选时长的片段以实际长度为限。不插入额外片头，不延长视频。
- 首期提供两种固定排版：简洁文字和带底色文字；支持有限字号、颜色与上／中／下位置，复用可用品牌色，不做自由图层编辑器。
- 最多两行，超出可容纳范围时清晰提示并要求缩短或调整字号，不能静默截字。默认避开字幕区域；重叠时给出提示及调整方式。
- 预览与导出使用相同布局、字体及时间范围。关闭标题后不留下占位。

### 5.3 封面

- 复用现有最终片段选帧能力；首期输出与视频相同比例的 JPG。
- 默认使用选中的片头标题初始化封面标题，之后独立编辑；再次同步标题必须由用户主动触发。
- 复用两种标题排版与已有品牌素材，不新增素材图库、AI 图片生成或跨项目品牌预设。
- 封面采用该时刻的最终画面构图与品牌设置，独立叠加封面标题；不叠加视频片头标题和动态字幕，避免重复文字。预览必须展示这一规则。
- 导出图片与封面预览一致。外部平台能否上传或选择该图片不在本功能承诺内。

### 5.4 发布文案

- 生成一组发布标题、简短正文和 0–5 个相关标签；正文默认 1–3 句，不为凑数量制造标签。
- 仅根据最终保留内容和用户修正后的文字生成；不把上下文中已剪掉的结论写进成片介绍。输入不足、转写为空或生成失败时支持手写。
- 不自动加入来源链接、嘉宾账号、赞助关系或行动号召；这些只有用户提供或手动填写后才使用。
- 标题、正文、标签分别编辑与复制，同时提供整体复制。用户文字优先，不自动覆盖。
- 首次生成统一返回草稿；后续允许针对标题或文案重新生成。候选结果先供用户选择，替换当前已编辑内容前明确确认。
- 默认复用已保存结果，不随开页、切换面板、换颜色或每次保存触发模型请求。

### 5.5 保存、内容变更与版本一致性

- 发布材料随当前片段保存，切换片段相互隔离；继承现有自动保存与冲突提示行为。
- 修改片段起止或字幕文字后，将已有生成标题和文案标记为“内容已修改，请核对”，保留人工编辑，不静默重写。用户可重新生成或确认继续使用。
- 调整颜色、布局等样式不使文案过期。只修改发布文案不要求重新渲染视频。
- 修改片头标题会使旧视频输出过期；修改封面文字只使封面过期。片段边界或构图变更按实际依赖使视频／封面过期。
- 选中的封面帧若被剪掉，提示重新选帧；不能继续把不在最终片段内的旧帧作为当前封面。
- 内容待核对不阻塞用户单独导出视频；完整发布包在核对完成后生成。
- ZIP 中的视频、封面与文字必须属于同一份确认后的发布快照。导出开始后继续编辑不会改动正在生成的包；旧结果明确标示为旧版本。

### 5.6 等待与失败

- 文案生成、视频渲染和封面生成分别展示状态；一次失败不清空已完成材料，也不把整个片段置为不可编辑。
- 重试只处理失败或变更部分，避免重复消耗。重复点击、网络重试和并发请求需服务端去重与限流。
- 视频或封面未就绪时不把 ZIP 标记为完成；可先下载已完成的单项。媒体过期或权限失效时说明原因，不能生成含失效链接的“成功”文件包。
- 生成失败仍可手写标题和文案、继续原有视频流程。

## 6. 套餐、成本与数据边界

- 首期沿用 `lib/video-workspace/access.ts`：Creator 与保留的 Basic 用户具备编辑权限，免费用户保留 AI 原始片段导出。方案不调整价格、视频额度、时长或素材保存期限。
- 首次按需求选片及一次零匹配调整向免费／付费用户开放，这是新增的产品权限决策，已在本地服务端实现；不增加成功候选批次，不增加转写分钟额度。记录额外分析成本，服务端固定限制调整次数。
- 新发布材料操作由服务端检查权限、项目归属和片段归属，不能只隐藏按钮。
- 首期不单独推出文案积分、不扣减转写分钟；采用服务端生成限流和已保存结果复用。具体限流数值在开发时结合模型成本测试确定，作为上线配置必填项，不宣传无限生成。
- 记录生成请求的必要用量与失败信息，复用现有运维机制；不建立新的用户追踪数据库或回放系统。
- 产品素材、标题、文案、文件名与媒体地址不进入分析事件。业务草稿按项目权限和现有删除／保留规则管理，不宣称永久保存。
- 首期沿用已有分析合同；若新增行为事件，必须先同步更新 allowlist 与跟踪文档。现有下载事件仅证明下载启动。

## 7. 明确不在首期的内容

已有候选后换主题／说话人重新找片、独立说话人筛选、多轮聊天式选片、视觉事件搜索、扩大视频时长合同、跨项目品牌预设、多条批量应用与导出、双人分屏、内部删句／去停顿、B-roll、背景音乐、翻译、社交账号连接、自动发布／排期、自动来源导入、团队审批和效果预测。零匹配的一次受控调整属于首期，不等于开放继续找片。

现有相关能力可以继续使用，但本期不扩展这些流程。博客、SEO 页面和广告也不属于本产品方案。

## 8. 实施拆分与已有能力复用

| 批次 | 交付 | 必须验证 |
| --- | --- | --- |
| 0：按意图选片 | 首次入口、需求校验与持久化、条件选片与复审、匹配理由、零结果与一次调整 | 默认流程、真实匹配、完整性、越界要求、并发计数、旧项目与短源路径 |
| A：数据与交互闭环 | 发布材料草稿、手动编辑、保存恢复、内容过期提示；跑通模型生成与替换确认 | 片段隔离、付费权限、冲突保护、不覆盖人工文字、限流与失败恢复 |
| B：画面包装 | 片头标题预览与渲染、封面标题预览与图片输出 | 字体与换行一致、字幕避让、标题时间范围、封面帧失效 |
| C：发布交付 | 当前片段发布快照、单项下载／复制、ZIP 与状态恢复 | 文件版本一致、过期结果识别、局部重试、旧草稿兼容 |

按 0 → A → B → C 实施，每批可单独验收；首期完成标准是整个流程可用。先交付可控选片，再接发布包装，不能仅在 UI 增加需求框却仍执行原来的无条件选片。

## 9. 验收与首轮用户验证

### 功能验收：以下全部满足才算首期完成

1. 付费用户从已有片段完成标题、封面和文案，刷新后恢复；免费原始导出不回归。
2. 三类标题含义与保存相互独立；片段 A 的修改不会污染片段 B。
3. 开关标题、长标题、不同字体与语言、字幕重叠场景均有明确可用行为，预览和导出一致。
4. 修改内容后能发现待核对文案；人工编辑保留；封面帧被剪掉时有明确修正路径。
5. 导出时继续编辑、生成失败重试、多标签页冲突等场景不会混用不同版本材料。
6. 下载的 ZIP 含实际 MP4、JPG 和文案文件，均能打开；没有失效媒体链接充当交付物。
7. 无权限访问、重复请求和限流均由服务端处理；日志与分析不泄露内容。
8. 完成相关 workspace 测试、locale 检查和生产构建；在实际本地视频环境中检查渲染与交互，不能仅凭单元测试认定画面正确。
9. 自动推荐不必填需求；按需求生成实际使用已确认的条件。已生成项目和短源直接编辑项目不会误触发新的候选分析。
10. 用原片中存在、不存在、相关但无法独立成片的主题分别验证；不匹配项不能补位，理由必须对应实际保留内容。对同一原片的不同有效需求能得到符合各自条件的结果，无需强求结果一定不同。
11. 越界指令、虚构前提、超长输入、无法确认的说话人身份得到明确处理，不绕过原文依据和时长限制。
12. 零匹配只允许一次主动调整；技术失败与正常空结果区分，刷新／并发不多扣次数，成功有候选后禁止换方向重选。条件和结果刷新后恢复，分析事件不含需求全文。

### 产品验证：判断下一步投入，不包装成市场证明

先准备 3–5 段有权使用的单人口播、访谈和知识讲解素材，包含需要纠错、长文字和不同构图的情况。在隔离测试环境对同一原片比较自动推荐和明确主题需求，预先人工标注能支持需求的区间以及应无结果的需求；不为测试开放生产无限重选。再用同一片段记录当前包装流程与首期流程的人工操作时间、处理等待时间、外部工具步骤和最终采用的材料。

随后邀请 3–5 位目标创作者用自己的任务试用，由其判断是否愿意发布、哪些内容还要重做。目标是多数试用者能完成流程，并至少有 3 位明确反馈减少了外部包装步骤；这是小样本方向信号，不是统计结论，也不是可对外宣传的效果数据。对外联系另行取得用户授权。

重点观察：

- 用户能否表达需求、候选是否匹配本次意图、无匹配解释是否准确，以及零结果调整能否帮助完成任务；不能为了降低零结果比例放松匹配标准。
- 视频能否直接采用，标题是否忠于原文，封面／文案是否被使用。
- 从选定片段到准备发布的主动操作时间，以及仍需打开的外部工具。
- 下一次真实制作是否再次使用发布准备，而非只看首次点击或下载。
- 每条被采用作品的生成与渲染成本；下载不等于实际发布，发布仅据用户自愿反馈或获授权记录确认。

后续顺序按证据调整：候选偏离要求则修匹配与完整性；有明确需求在同一素材中继续找不同主题，则做保留草稿、去重与成本明确的继续找片；包装被采用但重复操作多则做品牌预设与批量制作；持续成片后上传平台成为主要负担再接分发。首期验证不自动开启广告。
